# Lockfile (pack.lock)

`pack.lock` is an automatically generated file that records the exact resolved state of every dependency declared in `agentpack.toml`. It should be committed to version control and never edited by hand.

## Purpose

- **Reproducibility** — every developer and every CI run uses the same commit SHA and content hash, regardless of when they run `agentpack sync`.
- **Integrity** — content hashes let agentpack detect cache corruption or tampering before staging.
- **Auditability** — the lockfile is human-readable TOML, so `git diff pack.lock` clearly shows what changed between updates.

## Structure

```toml
# pack.lock — generated by agentpack. Do not edit manually.
version = 1

[[package]]
id      = "github.com/OlegHQ/paperclip-skills"
version = "0.3.2"
commit  = "a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2"
hash    = "sha256:e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"

[[package]]
id      = "github.com/acme/shared-rules"
version = "1.4.1"
commit  = "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef"
hash    = "sha256:abcdef1234567890abcdef1234567890abcdef1234567890abcdef1234567890ab"
```

### Fields per entry

| Field | Description |
|---|---|
| `id` | Module ID matching the key in `[dependencies]` |
| `version` | The resolved SemVer version |
| `commit` | Full Git commit SHA that was resolved |
| `hash` | SHA-256 of the downloaded archive (content-addressed) |

## Updating the lockfile

Run `agentpack lock` to recompute the lockfile from the current manifest:

```sh
agentpack lock
```

This fetches the latest matching tags from GitHub, resolves the full dependency graph, and rewrites `pack.lock`. It does not download content — that happens during `agentpack sync`.

## When to commit pack.lock

Always commit `pack.lock` for application projects and agent configurations. This ensures that every team member and CI run is using the exact same artifact versions.

For reusable packages that others will depend on, committing the lockfile is still recommended, but downstream projects will do their own resolution.

## Lockfile drift

If `pack.lock` is out of date relative to `agentpack.toml` (for example after editing the manifest by hand), agentpack will warn you. Run `agentpack lock` to reconcile.
